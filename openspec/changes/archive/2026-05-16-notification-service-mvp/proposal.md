## Why

Нужен микросервис уведомлений, который принимает массовые запросы на отправку SMS и Email, гарантированно доставляет сообщения через брокер сообщений, обеспечивает приоритезацию срочного трафика и даёт API для отслеживания статусов. Инфраструктурная обвязка уже подготовлена (Docker Compose со связкой app/nginx + worker + scheduler + PostgreSQL + RabbitMQ + Redis + Mailpit, базовые зависимости, переменные окружения, очереди `notifications.high`/`notifications.low`). Эта правка добавляет бизнес-логику сервиса поверх готовой инфраструктуры.

## What Changes

- Добавить REST API для массовой рассылки SMS/Email: один эндпоинт принимает канал, текст, массив получателей и приоритет.
- Добавить REST API получения истории и текущих статусов уведомлений по идентификатору подписчика.
- Реализовать асинхронный пайплайн доставки на двух уже сконфигурированных очередях RabbitMQ — `notifications.high` (срочные/транзакционные) и `notifications.low` (маркетинговые), с обработкой высоким приоритетом.
- Реализовать жизненный цикл статуса уведомления: `queued → sent → delivered | failed` с переходами из обработчика очереди и колбэков провайдера.
- Реализовать retry с экспоненциальной задержкой при временных ошибках провайдера (значения уже выставлены в команде воркера) и финальное отбрасывание после исчерпания попыток.
- Реализовать идемпотентность входящего API через заголовок `Idempotency-Key` (хранилище — Redis), а также дедупликацию обработки сообщений в воркере по `notification_id` (exactly-once-effect на уровне бизнес-логики).
- Добавить мок-провайдеры SMS и Email (классы-заглушки), имитирующие успех/временный/постоянный сбой по конфигурации. Email-провайдер дополнительно может отправлять через Mailpit (он уже в compose).
- Подключить OpenAPI/Swagger (через `dedoc/scramble`, уже в зависимостях) для документации API.
- Покрыть основные сценарии интеграционными тестами PHPUnit: приём API → запись в БД → публикация в RabbitMQ → обработка воркером → вызов мок-провайдера → переход статуса.
- Обновить `README.md` с инструкцией запуска, примерами вызовов и описанием API.

## Capabilities

### New Capabilities
- `notifications-api`: HTTP API для запуска массовой рассылки и чтения истории/статусов уведомлений конкретного подписчика; валидация, версионирование (`/api/v1`), OpenAPI-схема.
- `dispatch-pipeline`: асинхронная доставка через RabbitMQ — приоритезация транзакционных сообщений (`notifications.high` vs `notifications.low`), retry с backoff, вызов провайдера (SMS/Email), переходы статусов уведомления и персистентность в PostgreSQL.
- `idempotency`: защита от повторной отправки на уровне API (Idempotency-Key, Redis) и на уровне обработки сообщений в воркере (exactly-once-effect по `notification_id`).
- `provider-integration`: контракт провайдеров доставки и мок-реализации для SMS и Email с настраиваемой имитацией ошибок/задержек.

## Impact

- Код: новые модули в `app/` (доменные модели, DTO через spatie/laravel-data, сервисы, jobs, провайдеры; контроллеры в `Http/Controllers/Api/V1`; middleware идемпотентности; команда reconciler).
- БД: миграции для таблиц `notification_batches`, `notifications`, `notification_attempts`.
- Зависимости: всё нужное уже подключено (`vladimir-yuldashev/laravel-queue-rabbitmq`, `spatie/laravel-data`, `dedoc/scramble`, phpredis). Добавлять новые пакеты не требуется.
- Инфраструктура: правок compose не предполагается. Возможны мелкие подкрутки `.env.example` (флаги мок-провайдеров) и регистрация роутов/middleware в `bootstrap/app.php`.
- Тесты: интеграционные PHPUnit-тесты на реальных сервисах из docker-compose (Postgres/Redis/RabbitMQ), моки только для внешних SMS/Email-шлюзов.
- Документация: README.md (бизнес-описание, примеры curl, как смотреть письма в Mailpit и сообщения в RabbitMQ UI), OpenAPI на `/docs/api`.
